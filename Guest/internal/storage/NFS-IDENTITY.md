# Shared-volume NFS identity

The service-owned export root is made searchable (`0755`) before serving; administrative-service creation order must not leave it at `0700`. Named-volume roots keep their own ownership and permissions.

The storage export requires validated RFC 5531 AUTH_SYS on every non-NULL RPC. UID, primary GID, and up to 16 supplementary GIDs are asserted separately on each request; AUTH_NONE, unsupported flavors, malformed bodies, and Linux's reserved `-1` IDs are rejected. The verifier must be AUTH_NONE. This is a trusted guest-to-storage transport, **not cryptographic authentication**: any client that can reach it can claim UID 0. Root is deliberately not squashed, so container-root initialization and copy-up retain Linux ownership semantics. Do not expose this service to untrusted networks or tenants without an authenticated transport and export policy.

RPC records are size-bounded, admitted against a server-wide 64 MiB receive budget, and received completely before entering an identity scope; 30-second receive/write deadlines and context-driven connection close prevent incomplete requests or non-reading peers from retaining resources indefinitely. At most 64 identity scopes run concurrently. FIFO/device/socket data opens are rejected after an O_PATH type check and before any data open; regular files/directories are reopened only through that pinned descriptor; character/block node creation is rejected even for root, since os.Root cannot confine device I/O. The helper root descriptor is derived from the same os.Root, not a second path lookup.

Every request runs synchronously on a fresh locked Go OS thread. Only raw Linux thread-local credential syscalls are used; libc/Go process-wide set-id wrappers are prohibited. All real/effective/saved UIDs and GIDs and supplementary groups are replaced, and all effective/permitted/inheritable capabilities are explicitly cleared for nonzero UIDs. UID 0 retains the service's capabilities. The worker exits **without `UnlockOSThread`**, so Go terminates the OS thread even after partial credential-installation failure or a recovered callback panic. No restoration is attempted and no credentialed thread returns to the scheduler. Go's `LockOSThread` starts its clean template thread before any credential change (`runtime/proc.go`), preventing new runtime threads from inheriting request credentials. Callbacks must not launch goroutines or retain file descriptors beyond their request.

Linux enforces DAC, directory search/write permissions, supplementary groups, setgid inheritance, sticky directories, ownership changes, ACLs, and capability restrictions on the actual filesystem operations. ACCESS uses `faccessat2`-equivalent effective-identity checks on pinned O_PATH descriptors, plus parent/sticky checks for DELETE. Namespace and metadata operations use `os.Root`; special-node creation and ACCESS use pinned `openat2` descriptors. Absolute/escaping symlink targets cannot be followed outside the export. Existing handle maps and copy-up exclusive rename bookkeeping are retained.

Contracts: RFC 5531 sections 8.2 and 9 (AUTH_SYS); RFC 1813 sections 3.3.2–3.3.15 (NFSv3 permissions/operations); Linux `credentials(7)`, `capabilities(7)`, `setresuid(2)`, `setgroups(2)`, `faccessat2(2)`, `openat2(2)`; Go `runtime.LockOSThread` and `os.Root` contracts. Linux with openat2/faccessat2 support and a root service holding SETUID/SETGID is required; there is no permissive fallback.

Tests: `cd Guest/third_party/go-nfs && go test ./...`; on Linux root, `cd Guest && go test -mod=mod ./internal/storage -run 'TestNFS'`. `RTM-053`/`RTM-054` cover direct/shared volume metadata and live NFS identities in the isolated VM harness. Run `go mod vendor` from `Guest` after changing the maintained fork. Per-RPC OS-thread creation favors isolation over throughput; benchmark before introducing thread reuse, and never add credential restoration without failure-path and concurrency review.
